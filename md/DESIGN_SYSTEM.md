## 1. 产品定位

**一句话定位**：玄机是一款以 AI 为内核、以东方神秘学为外衣的情绪陪伴型占卜工具。

核心价值三角：

- **占卜**（仪式感驱动的卦象/塔罗推演）
- **解读**（AI 以温和智者的口吻给予情感回应）
- **陪伴**（记忆用户情绪轨迹，形成长期信任关系）

与竞品的差异：

- 不做玄学工具（不对标"易经大全"类 App）
- 不做纯聊天机器人（不对标 Character.AI）
- 做"占卜媒介 + 情绪容器"——用户来占卜，留下来是因为被理解

## 2. 用户画像

### 核心用户 A：小雅（25 岁，一线城市职场女性）

- 焦虑来源：职业方向迷茫、感情不确定性
- 使用场景：深夜 11 点睡前，独自在卧室
- 行为模式：每周 1-2 次，每次逗留 8-15 分钟
- 核心需求：不是"要一个正确答案"，而是"被认真倾听和温柔回应"
- 审美敏感度：高——UI 丑会直接流失

### 次要用户 B：阿哲（30 岁，互联网从业者）

- 使用场景：重大决策前"求个心安"
- 行为模式：低频但深度使用，每次认真阅读解读内容
- 核心需求：解读要有逻辑层次，不要"正确的废话"
- 对六爻/塔罗有一定了解，会较真专业准确性

### 设计决策

- 以**小雅为第一优先级**设计交互节奏和情绪反馈
- 以**阿哲的需求**保障解读内容的专业深度
- 不做任何"二次元萌系"风格，排除低龄用户

## 3. 品牌关键词

| 维度 | 关键词 |
|------|--------|
| 调性 | 沉静、深邃、克制、温柔 |
| 意象 | 月光、铜钱、烛火、墨痕、星图 |
| 情绪 | 被接住、被看见、被轻轻托起 |
| 拒绝 | 喧哗、浮夸、廉价炫技、赛博朋克 |

品牌命名原则：

- "玄机" 二字拆解：玄 = 深奥不可测，机 = 转机/契机
- 英文可用 **Xuanji** 或 **Arcana**，但主品牌只出中文
- Logo 方向：极简线条的铜钱 + 星芒几何，不出现具象塔罗牌面

## 4. UI 风格关键词

**五字核心**：暗 · 暖 · 透 · 稳 · 藏

| 关键词 | 视觉表达 |
|--------|----------|
| 暗 | 深色基底，不是纯黑，是带灰蓝底色的"夜空" |
| 暖 | 金色/琥珀色作为唯一强调色，类似烛光色温 |
| 透 | 毛玻璃、半透明层叠，营造"雾中窥见"的朦胧感 |
| 稳 | 字距宽松、行距从容，没有拥挤感 |
| 藏 | 信息分层渐进，不一次性倾泻，保留探索感 |

**禁止风格**：

- 赛博朋克霓虹（与神秘学调性冲突）
- 极简白底（无"仪式空间"的氛围）
- 卡通/二次元（排除低龄感）
- Material Design 套壳（Google 味太重，破坏神秘感）

### 5.2 配色原则

1. **80/15/5 比例**：80% 深色背景，15% 半透明层叠，5% 金色强调
2. 金色只用于：卦名、牌名、关键数字、选中态、核心 CTA、分割装饰线
3. 红色仅用于：塔罗逆位警告、错误提示
4. 绝不在正文中使用金色——正文永远是 `stone` 系
5. 渐变方向统一：`150deg`（从左上到右下），模拟烛光方向

## 6. 字体系统

### 6.1 字体族

| 层级 | 字体 | 用途 |
|------|------|------|
| 标题 | `'Noto Serif SC', 'Source Han Serif SC', '宋体', serif` | 页面标题、卦名、牌名 |
| 正文 | `system-ui, -apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif` | 所有正文、按钮、标签 |
| 古文引用 | 继承标题字体 | 卦辞、彖辞、《象》曰引用 |
| 数字/英文 | `'Cormorant Garamond', 'Playfair Display', serif`（可选，后续迭代加载） | 装饰性数字 |

### 6.2 字号阶梯

```
┌──────────────┬──────────┬─────────────────────────────────┐
│  Token        │  大小     │  用途                           │
├──────────────┼──────────┼─────────────────────────────────┤
│  text-xs      │  0.75rem │  辅助标注、时间戳、英文名        │
│  text-sm      │  0.875rem│  正文、卡片内描述、按钮文字       │
│  text-base    │  1rem    │  重要正文段落                    │
│  text-lg      │  1.125rem│  卦辞引用、AI 解读标题           │
│  text-xl      │  1.25rem │  副标题                         │
│  text-2xl     │  1.5rem  │  变卦名、牌名（小）              │
│  text-3xl     │  1.875rem│  卦名、牌名（大）、页面标题       │
│  text-4xl     │  2.25rem │  Landing 大标题                  │
│  text-5xl     │  3rem    │  仅品牌标识/Hero                 │
└──────────────┴──────────┴─────────────────────────────────┘
```

### 6.3 字重

- 标题：`font-normal` (400) —— 中式审美忌粗重，留白即力量
- 正文：`font-normal` (400)
- 强调文本：`font-medium` (500)，用 `text-amber-200` 而不是加粗
- 不用 `font-bold` (700)，粗体在中文排版中显得压迫

### 6.4 行高 & 字距

- 正文行高：`leading-relaxed` (1.625)
- 标题行高：`leading-tight` (1.25)
- 古文引用行高：`leading-loose` (2)，模拟古籍排版
- 卦名/牌名字距：`tracking-widest` (0.1em)
- 正文不设额外字距（`tracking-normal`）

### 6.5 排版禁忌

- 中文段落在卡片内最大宽度 `max-w-prose`（65ch），超出换行
- 不在正文中使用斜体（中文无 italic 传统），仅英文牌名用 `italic`
- 英文牌名统一用 `text-xs` + `text-stone-500`

```
│  gap-12       │  48px    │  页面级区块分割        │
│  gap-16       │  64px    │  Landing 段间距        │
├──────────────┼──────────┼──────────────────────┤
│  p-4          │  16px    │  卡片内边距（默认）    │

└──────────────┴──────────┴──────────────────────┘
```

### 7.3 布局间距

- 页面内容区水平内边距：`px-4`（移动端）/ `px-8`（桌面端）
- 页面顶部留白：`pt-16`（考虑固定导航栏）
- 页面底部留白：`pb-12`
- 所有相邻卡片间距：`gap-4`

### 7.4 容器宽度

| 容器 | 最大宽度 | 用途 |
|------|----------|------|
| 阅读型容器 | `max-w-prose` (65ch) | AI 解读正文、卦辞 |
| 卡片型容器 | `max-w-2xl` (672px) | 六爻/塔罗结果卡片 |
| 页面主体 | `max-w-5xl` (1024px) | 塔罗牌阵 |
| Landing | `max-w-6xl` (1152px) | 首页内容区 |

## 8. 动效规范

### 8.1 动效哲学

- **目的**：服务仪式感，不是炫技
- **节奏**：偏慢、偏柔，留有呼吸感
- **铁律**：任何用户触发的交互动画不超过 500ms，占卜仪式动画不超过 1500ms

### 8.2 标准缓动曲线

```
┌──────────────────────┬──────────────────────────────────────┐
│  场景                 │  缓动                                │
├──────────────────────┼──────────────────────────────────────┤
│  入场（卡片/组件）     │  ease-out：cubic-bezier(0,0,0.2,1)  │
│  退场                 │  ease-in：cubic-bezier(0.4,0,1,1)    │
│  悬停反馈             │  ease：cubic-bezier(0.4,0,0.2,1)    │
│  仪式动画（占卜）      │  自定 cubic-bezier(0.34,1.56,0.64,1)│
│  滚动触发             │  linear                              │
└──────────────────────┴──────────────────────────────────────┘
```

Framer Motion 实现：

```ts
const EASING = {
  enter: [0, 0, 0.2, 1],
  exit: [0.4, 0, 1, 1],
  hover: [0.4, 0, 0.2, 1],
  ritual: [0.34, 1.56, 0.64, 1], // 轻微弹性
} as const;
```

### 8.3 动画时长

```
┌──────────────────────────────┬──────────┐
│  场景                         │  时长     │
├──────────────────────────────┼──────────┤
│  悬停过渡（opacity/color）     │  150ms   │
│  悬停过渡（scale/translate）   │  200ms   │
│  卡片入场（stagger）           │  每张30ms │
│  翻牌动画（塔罗）              │  600ms   │
│  铜钱落定（六爻）              │  700ms   │
│  面板展开                     │  300ms   │
│  页面切换                     │  300ms   │
│  Loading 脉冲                 │  2000ms（循环）│
│  AI 文字逐字打印              │  30ms/字  │
└──────────────────────────────┴──────────┘
```

### 8.4 动画层级规则

1. **所有入场动画**使用 `motion.div` + `variants`，延迟通过 `custom` 索引控制
2. `staggerChildren` 用于列表/牌阵的逐项入场
3. 页面级过渡使用 `AnimatePresence` + `mode="wait"`
4. **严禁**：无限循环的旋转/弹跳动画（降低信任感）
5. **禁止**：scroll-driven 视差（移动端性能灾难 + 眩晕）

### 8.5 微交互

| 交互 | 效果 |
|------|------|
| 按钮悬停 | `scale(1.02)` + 发光扩散（`box-shadow` 过渡） |
| 卡片悬停 | `translateY(-2px)` + 边框亮度提升 |
| 点击反馈 | `scale(0.97)` + 100ms 后恢复 |
| 加载状态 | 单点呼吸脉冲，非旋转 spinner |
| 成功状态 | 金色短暂闪烁 (`opacity: 0 → 1`) |
| 错误状态 | 红色边框闪烁一次 + 抖动 (`x: [0, -4, 4, -4, 0]`) |

- 卡片居中：`mx-auto`
- 多卡片容器使用 `flex flex-col gap-4`

## 10. 按钮规范

### 10.1 按钮层级

| 层级 | 类名 | 视觉 | 用途 |
|------|------|------|------|
| 主按钮 | `btn-primary` | 金色半透明底 + 金色文字 + 金色边框 | 核心 CTA（起卦、请求解读） |
| 次按钮 | `btn-secondary` | 白色 5% 底 + 灰色文字 | 次要操作（重置、返回） |
| 文字按钮 | `btn-ghost` | 无背景 + 悬停变亮 | 导航、模式切换 |
| 危险按钮 | `btn-danger` | 红色半透明底 | 删除、退出 |

### 10.2 按钮规格

```
┌──────────────────┬──────────┬──────────┬───────────┐
│  属性              │  sm      │  md(默认) │  lg       │
├──────────────────┼──────────┼──────────┼───────────┤
│  padding-x        │  px-4    │  px-6    │  px-8     │
│  padding-y        │  py-2    │  py-3    │  py-4     │
│  font-size        │  text-xs │  text-sm │  text-base│
│  border-radius    │  rounded-lg│ rounded-xl│ rounded-xl│
└──────────────────┴──────────┴──────────┴───────────┘
```

### 10.3 按钮状态

每个按钮必须覆盖以下状态：

- `default`：正常态
- `hover`：亮度 + 微放大
- `active`：微缩小（按压反馈）
- `disabled`：opacity 降至 40%，cursor 变为 `not-allowed`，禁止 hover 效果
- `focus-visible`：金色 outline ring（键盘导航）

### 10.4 主按钮 CSS

```css
.btn-primary {
  @apply px-6 py-3 rounded-xl font-medium transition-all duration-200
         bg-amber-200/10 text-amber-200 border border-amber-200/20
         hover:bg-amber-200/20 hover:shadow-[0_0_24px_rgba(253,230,138,0.18)]
         active:scale-[0.97]
         disabled:opacity-40 disabled:cursor-not-allowed
         disabled:hover:bg-amber-200/10 disabled:hover:shadow-none
         disabled:active:scale-100
         focus-visible:outline-none focus-visible:ring-2
         focus-visible:ring-amber-200/40 focus-visible:ring-offset-2
         focus-visible:ring-offset-[#0a0c0f];
}
```

### 10.5 按钮文案规范

- 不使用符号代替文字（如 ✨ 代替"开始占卜"）
- 不使用纯英文 CTA
- 按钮文案长度 2-6 字

## 12. 仪式感交互设计

### 12.1 仪式感定义

仪式感 = **时间的刻意拉长 + 视觉的阶段性反馈 + 不可逆的单向流程**

用户来占卜，不是来"查资料"。每一次点击都应该有分量。

### 12.2 六爻占卜仪式流程

```
[输入问题] → [起卦按钮]
    │
    ▼
[动画阶段]  铜钱抛出动画 (700ms)
    │         ├─ 铜钱升起
    │         ├─ 铜钱旋转
    │         └─ 铜钱落定 → 爻线出现
    │
    ▼
[结果阶段]  按钮文案变为"再摇一爻"（逐爻推进）
    │        6 次后 → 按钮变为"解卦"
    │
    ▼
[解卦阶段]  AI 逐字打印解读（模拟"智者正在沉吟"）
    │
    ▼
[完成]      金色微光闪过，卦象完整呈现
```

关键规则：

- 动画期间按钮**完全禁用**，不可连点
- 动画结束后才更新爻线状态（通过 `onAnimationComplete` 回调）
- 每次摇爻之间有 300ms 的视觉停顿

### 12.3 塔罗占卜仪式流程

```
[输入问题] → 22 张牌阵渐入（stagger 动画，每张 30ms 延迟）
    │
    ▼
[选牌阶段]  用户悬停哪张，哪张微升 + 亮边框
    │        点击 → 牌翻转 600ms（卡背 → 牌面）
    │
    ▼
[翻牌阶段]  翻牌动画 (rotateY 0→180)
    │        牌面从模糊到清晰
    │        正位/逆位判定（50% 概率）
    │
    ▼
[解读阶段]  详情面板从牌中"生长"出来
    │        AI 逐字打印解读
```

关键规则：

- 牌阵入场有 stagger 延迟，营造"命运之轮展开"的感觉
- 选中一张牌后，未选中的牌略微变暗（opacity 0.4）
- 翻牌方向：从下往上翻转（`rotateX`），模拟真正翻开一张牌
- 逆位时出现红色警示线

### 12.4 过渡页面

占卜模式切换时：内容区 `opacity` 淡入淡出（300ms），不做滑动切换。

### 12.5 音效预留

当前版本不实现音效，但预留接口。后续可加入：

- 铜钱碰撞声（低频 "叮"）
- 翻牌声（纸张摩擦）
- AI 回复到达提示（单音阶）

所有音效必须是低频、短促的，不能是手机通知音。

## 13. 情绪化设计原则

### 13.1 核心原则

**占卜的结果不是答案，是情绪的容器。**

设计的每个决策都要问自己：**"小雅在深夜打开这个页面时，会感到被温柔对待吗？"**

### 13.2 文案情绪层级

| 场景 | 语气 | 示例 |
|------|------|------|
| 引导 | 邀请式，不催促 | "心中默念你的问题，然后起卦" |
| 等待 | 留白式，不安抚 | "……"（让用户自己沉淀） |
| 结果 | 陈述式，不评判 | "这一卦显示……" |
| 安慰 | 共情式，不说教 | "不确定本身，也是答案的一部分" |
| 错误 | 承担式，不推锅 | "玄机未显，请稍后再试" |

### 13.3 视觉情绪映射

| 用户情绪 | 视觉反应 |
|----------|----------|
| 平静探索 | 正常金色，静态布局 |
| 期待结果 | 金色微光增强，动画速度略快 |
| 获得解读 | AI 文字逐字浮现，温柔"揭示"感 |
| 焦虑等待 | 呼吸式 loading 脉冲，不慌不忙 |
| 失望/错误 | 红色警示但克制，提供重新开始的出口 |

### 13.4 Loading 状态的情绪化设计

**禁止**：转圈 spinner（传达"系统在忙，你等着"）

**采用**：

- 呼吸式光点："……" 三个点依次明灭，周期 2s
- 文案："正在感应你的问题……"（主动语态）
- 错误兜底文案："此刻不宜问卦，换个时间再来吧"（主动承担责任，不让用户觉得是自己的问题）

### 13.5 空状态设计

- 六爻未起卦：展示一个空白的爻线占位图（虚线勾勒），文字提示"默念问题，点击起卦"
- 塔罗未选牌：22 张卡背整齐排列，等待触碰
- 未输入问题：输入框 placeholder 使用引导式文案，如"你想问什么？"

## 14. 移动端适配规范

### 14.1 断点策略

```

├─────────────┼──────────┼──────────────────────┤
```

### 14.2 Mobile-First 原则

- 所有样式从移动端出发，用 `md:` / `lg:` 前缀增强桌面端
- 不在移动端隐藏核心功能

|------|------|
| 塔罗牌阵（22 张） | 移动端每行 5-6 张，牌缩小到 52×84px |

| 导航栏 | 移动端高度不变，按钮缩小到 `px-4 py-1.5` |
| 输入框 | 移动端全宽，`text-base` 防止 iOS 自动缩放 |
| 触摸反馈 | 使用 `active:` 伪类 + `touch-action: manipulation` |
| 安全区 | `pb-safe` 适配 iPhone 底部横条 |

### 14.4 桌面端增强

- 塔罗牌阵每行 11 张，牌尺寸 72×112px
- 卡片支持 hover 微升效果
- 解读文本 `max-w-prose` 居中
- 键盘导航完整支持（`focus-visible`）

### 14.5 响应式 Tailwind 类规范

```
移动端默认 → md: → lg: → xl:
不写 sm: 前缀（sm 是 640px，已属于平板范畴）
```

示例：
```html
<div className="px-4 md:px-8 lg:px-0 lg:max-w-2xl lg:mx-auto">
```

## 16. 占卜流程结构

### 16.1 通用占卜流程

两种占卜模式共享同一底层流程：

```
[输入问题] → [执行占卜仪式] → [获取结果] → [AI 解读] → [完成]
```

### 16.2 状态机

每种模式内部严格使用状态机驱动：

```
六爻：idle → throwing → idle → ... (循环6次) → completed
塔罗：idle → drawing → drawn
```

UI 渲染完全由状态机阶段决定，不得通过额外的 boolean 标志控制。

### 16.3 问题输入

- 两种占卜共享同一个问题输入组件 `QuestionInput`
- 占卜期间（`throwing` / `drawing` / `drawn`）输入框禁用
- 占卜完成后允许修改问题（触发重置）
- Placeholder 文案根据模式不同：
  - 六爻："你想问什么？（例如：这次跳槽时机对吗？）"
  - 塔罗："默念你的问题，然后选择一张牌"

### 16.4 结果展示

- 先展示占卜结果（卦象/牌面），再展示 AI 解读
- 占卜结果与 AI 解读之间有明确视觉分隔
- AI 解读区支持"通俗/专业"切换（六爻）
- 解读完成后出现"重新开始"按钮

### 16.5 流程约束

- 每个占卜会话是单向的：不能"回退到上一步"
- "重新开始"是唯一的回溯出口
- 同一卦象不允许重复请求 AI（防止重复扣费 + 结论冲突）

## 17. AI 对话体验结构

### 17.1 当前阶段

当前版本不实现多轮对话，仅做单次请求-响应式解读。

### 17.2 单次解读体验

```
[用户操作：点击"请求解读"]
    │
    ▼
[发送阶段] 按钮变为 loading 态，文案"正在感应……"
    │
    ▼
[接收阶段] AI 文本逐字打印（typewriter effect）
    │         速度：约 30ms/字
    │         光标：闪烁竖线
    │
    ▼
[完成阶段] 光标消失，出现"重新开始"按钮
```

### 17.3 逐字打印的仪式意义

- 不是炫技——是模拟"智者正在为你沉吟"的感觉
- 用户不能快进（避免"刷答案"心态）
- 速度不能太慢（超过 3 秒无新字出现就焦虑）

### 17.4 错误处理

```
┌──────────────────────────────────────┐
│           ╱ ╲                        │
│          ╱   ╲                       │
│         ╱     ╲                      │
│        ╱   ✧   ╲                     │
│       ╱         ╲                    │
│      ╱___________╲                   │
│                                      │
│    玄机未显，请稍后再试                │
│                                      │
│    [重新开始]                         │
└──────────────────────────────────────┘
```

- 使用占卜相关的隐喻文案，而非"网络错误，请重试"
- 不展示技术细节（状态码、错误栈）
- 提供明确的重新开始入口

### 17.5 后续多轮对话的预留

- 设计上预留对话历史区域（`chat-history`）
- AI 回复组件已经是独立的 `ResultCard`，便于后续替换为对话气泡列表
- Context 中预留 `conversationHistory` 字段（当前版本不启用）

## 18. 高级感设计原则

### 18.1 什么是"高级感"

在这个产品的语境下，高级感 = **克制的奢华**。不是用更多特效，而是用更少的元素传达更深的情绪。

### 18.2 十大高级感原则

1. **少即是多**
   - 每个页面只突出一个核心动作
   - 装饰元素不超过 3 处

2. **留白即呼吸**
   - 卡片之间至少 16px 间距
   - 内容绝不到边——永远有 padding
   - 标题与正文之间有明确的高低差

3. **一个强调色**
   - 金色是唯一的强调色
   - 不在同一页面使用超过 3 种颜色
   - 渐变色只用于装饰，不用于正文

4. **字体即气质**
   - 衬线字体（宋体/Noto Serif）只在标题出现
   - 正文用系统无衬线，确保可读性
   - 字号变化不超过 4 个层级

5. **透明度即层次**
   - 用 `rgba(255,255,255,0.03)` 到 `0.15` 的递进区分层次
   - 毛玻璃 `backdrop-blur` 创造悬浮感
   - 从不用纯白边框（`border-white/10` 是底线）

6. **动效即尊重**
   - 动画服务于流程，不打断用户
   - 入场有先后（stagger），退场干脆
   - 从不使用弹跳/旋转/无限循环动画

7. **文案即人格**
   - 每一句文案都经过推敲
   - 不说"正在加载中……"，说"正在感应你的问题……"
   - 错误不推锅给用户

8. **细节即诚意**
   - 按钮的 disabled / hover / active / focus 四个状态齐全
   - 输入框有 focus 边框发光
   - 选中态有明确视觉反馈

9. **一致性即信任**
   - 所有卡片遵循同一套圆角/间距/边框规则
   - 所有按钮遵循同一套状态规范
   - 所有动画遵循同一套缓动曲线

10. **隐私即尊严**
    - 不追踪、不弹窗要权限
    - 问题输入框下方标注"你的问题仅用于本次解读，不会被存储"
    - 没有社交分享按钮

## 19. 禁止出现的低级设计

以下设计一旦出现，直接破坏产品的"高级感"和用户信任：

### 19.1 视觉类禁止

| 禁止 | 原因 |
|------|------|
| 纯黑 `#000000` 背景 | 刺眼，无层次感 |
| 纯白 `#FFFFFF` 文字 | 在深色背景上过于刺眼 |
| 超过 3 种以上的颜色 | 廉价感 |
| 渐变文字（`bg-clip-text`） | 破坏可读性 |
| 阴影过重（`shadow-2xl`） | 浮夸 |
| 圆角超过 `rounded-3xl` | 胶囊感破坏神秘感 |
| Emoji 作为 UI 元素 | 不专业 |
| 闪烁/彩虹色动画 | 低端页游既视感 |

### 19.2 交互类禁止

| 禁止 | 原因 |
|------|------|
| 自动播放音频 | 侵扰用户 |
| 弹窗广告 / 评分弹窗 | 破坏沉浸 |
| 无限滚动加载 | 用户无法定位 |
| 双击才能触发的操作 | 不符合移动端习惯 |
| 没有 disabled 状态的按钮 | 用户困惑 |
| 没有 loading 状态的异步操作 | 用户不知道是否生效 |
| 没有错误处理的网络请求 | 白屏/卡死 |

### 19.3 文案类禁止

| 禁止 | 原因 |
|------|------|
| "点击这里" | 不描述操作目的 |
| "错误：500 Internal Server Error" | 暴露技术细节 |
| "恭喜你！" | 占卜不是抽奖 |
| "运势极佳！" | 过度承诺，破坏信任 |
| 英文未经翻译 | 目标用户是中文用户 |
| 超过 10 个字的按钮文案 | 按钮不是段落 |

### 19.4 技术类禁止

| 禁止 | 原因 |
|------|------|
| `any` 类型 | 破坏类型安全 |
| 内联 style 对象（除非动态计算值） | 破坏样式一致性 |
| 超过 200 行的组件文件 | 违反单一职责 |
| 硬编码 API Key | 安全漏洞 |
| 不处理 AbortController | 内存泄漏 |
| 没有 Error Boundary | 整体白屏 |

## 20. React 组件拆分规范

### 20.1 拆分原则

**三层结构**：

```
Page（页面容器）→ Section（功能区块）→ UI Component（可复用原子）
```

- **Page**：路由绑定的顶层组件，负责组装 Section、管理页面级状态
- **Section**：一个完整的功能区块（如"牌阵区"、"解读区"），可含多个 UI Component
- **UI Component**：纯展示或单一交互，无业务逻辑

### 20.2 目录结构

```
src/
├── components/
│   ├── common/              ← 跨模块复用的纯 UI 组件
│   │   ├── QuestionInput.tsx
│   │   ├── ResultCard.tsx
│   │   ├── LoadingSpinner.tsx
│   │   └── TypewriterText.tsx     （后续新增）
│   ├── IChing/              ← 六爻专属组件
│   │   ├── IChingPage.tsx         （Page）
│   │   ├── IChingBoard.tsx        （Section：爻线展示）
│   │   ├── ThrowButton.tsx        （UI Component：起卦按钮）
│   │   └── Coin.tsx               （UI Component：单枚铜钱）
│   └── Tarot/               ← 塔罗专属组件
│       ├── TarotPage.tsx          （Page）
│       ├── TarotCard.tsx          （UI Component：单张牌）
│       ├── TarotSpread.tsx        （Section：牌阵区，后续拆分）
│       └── TarotDetail.tsx        （Section：详情面板，后续拆分）
├── hooks/                   ← 自定义 Hooks（业务逻辑）
├── utils/                   ← 纯函数工具
├── constants/               ← 静态数据
├── types/                   ← 类型定义
└── context/                 ← 全局 Context
```

### 20.3 组件大小约束

| 类型 | 最大行数 | 最大职责数 |
|------|----------|------------|
| UI Component | 150 行 | 1 个职责 |
| Section | 200 行 | 组装 ≤5 个子组件 |
| Page | 250 行 | 组装 ≤4 个 Section |
| Hook | 200 行 | 1 个领域 |

超过上限即拆分。

### 20.4 组件接口规范

每个组件文件必须导出明确的 Props 类型：

```tsx
// ✅ 正确
import type { ReactNode } from 'react';

interface ThrowButtonProps {
  phase: IChingPhase;
  currentThrow: number;
  onThrow: () => void;
}

export function ThrowButton({ phase, currentThrow, onThrow }: ThrowButtonProps): ReactNode {
  // ...
}
```

```tsx
// ❌ 错误：无类型、any、默认导出不一致
export default function ThrowButton(props) {
  // ...
}
```

### 20.5 状态管理规范

- **页面级状态**：在 Page 组件中用 `useState` / `useReducer`
- **跨页面共享**：通过 `AppContext`（当前仅 `question`）
- **路由状态**：从 URL 派生，不存入 Context
- **不引入 Redux / Zustand**：当前规模不需要

### 20.6 组件命名规范

- 文件名与组件名一致：`ThrowButton.tsx` → `export function ThrowButton`
- 默认导出仅用于 Page 组件（路由绑定的顶层）
- 其他组件一律命名导出

### 20.7 样式应用规范

- 使用 Tailwind 类名，不写 `.css` 文件（除 `index.css` 全局样式）
- 自定义样式抽取到 `index.css` 的 `@layer components` 中
- 组件内不出现 `style={{}}`，除非是 Framer Motion 动态值
- 条件类名使用模板字符串，不用 `classnames` 库：

```tsx
className={`px-4 py-2 rounded-lg ${
  isActive ? 'bg-amber-200/10 text-amber-200' : 'text-stone-400'
}`}
```

### 20.8 可访问性（a11y）最低要求

- 所有按钮提供 `aria-label`（如果没有可见文字）
- 交互元素支持 `Tab` 键导航
- `focus-visible` 样式完备
- 图标提供 `aria-hidden="true"` 或替代文本
