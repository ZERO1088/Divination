# 页面视觉重构方案

> 日期：2026-05-25
> 状态：方案阶段，尚未实施
> 目标：从"功能展示"转向"情绪体验"，改变页面观感而非工程结构

---

## 诊断

当前三个页面的共同问题：**空间关系完全扁平**。所有内容以 `flex-col gap-4` 线性堆叠，如同阅读一份文档。每张牌、每个卦象、每条 AI 输出都被同等对待——像一个展示所有功能的仪表盘，而不是引导用户进入某种情绪状态的空间。

视觉注意力没有落脚点。用户进来后不知道该看哪里，于是从上到下扫一遍就走。

---

## 一、Tarot 页面重构

### 核心隐喻：「聚光灯舞台」

用户进入页面后，22 张大牌铺满整个屏幕，但所有牌都处于**低可见度**状态——像是黑暗房间里隐约可见的物件。用户点击一张牌后，那一刻必须构成整个体验的视觉高潮。

### 阶段 1：选牌前

**当前问题：** 牌阵是两排整齐的 flex-wrap 网格，每张牌 88×136px，观感像扑克牌桌面游戏。

**改变方向：**

- 22 张牌应铺展在整个视口内，不再限于 max-w-5xl 的约束带
- 扇形排列保留，但角度和间距放得更开，让牌阵像"散落在深色丝绒上的牌"，而非 UI 网格
- 每张牌略微放大至约 100×155px
- 全部牌初始 opacity 约 0.4–0.55，hover 时升至 0.8
- 牌阵后方有极淡的径向光晕，暗示舞台存在
- 页面顶部不再有 h1 标题「塔罗抽牌」——标题应是氛围的一部分而非功能标签

### 阶段 2：选中牌——视觉主角诞生

**这是整个页面最关键的视觉事件。** 当前实现：选中牌在网格中加了一圈金辉 glow，大小不变，位置不变。

**改变方向：**

- 选中牌必须**脱离网格**，动画：从原位 lift → scale ×3.5~4 → 移动到视口正中央
- 移动过程中，非选中牌集体执行：opacity → 0.08，filter: blur(8px)，scale → 0.92
- 选中牌到达中心后，其背后出现聚光灯效果：`radial-gradient(ellipse, rgba(253,230,138,0.12) 0%, transparent 70%)`，直径约 500px
- 选中牌自身尺寸达到约 220×340px（从 88×136 放大），确保牌面细节可读
- 牌面增加微弱的浮动动画（translateY ±6px，周期 8s）
- 背景整体暗度增加（叠加一层黑色半透明遮罩）

### 阶段 3：牌面揭示——侧翼展开

**当前问题：** CardReveal 是牌阵下方的一个 glass-card 面板，位置与牌断开。

**改变方向：**

- 揭示信息不应在"下方"，而应在选中牌的**右侧展开**
- 布局变为：左侧（占 40% 宽度）= 选中牌悬浮居中；右侧（占 60%）= 揭示面板
- 揭示面板从右侧滑入，带有微妙的"光之丝线"连接牌与面板
- 牌名以大字（text-3xl）呈现，正逆位通过色彩和方向暗示（正位 = 金，逆位 = 暗红 + 轻微旋转）
- 关键词以独立浮动标签形式出现，每个标签从牌面方向"飘出"并定位
- 含义文字带引用装饰（「」+ 左侧金线），字号适当放大，段落间隔加大
- 「请求解读」按钮置于揭示面板底部，视觉上是一道"门"而非普通按钮

### 阶段 4：AI 解读——命中句先行

**当前问题：** AIResponseCard 直接出现在揭示面板下方，是一块普通的 glass-card。

**改变方向：**

- 揭示面板收起后（或选中牌保持悬浮），页面中央出现**一句「命中句」**
- 命中句：居中、serif 字体、text-2xl~3xl、琥珀金色
- 上下各留至少 120px 空白
- 命中句以慢速 typewriter 逐字浮现（每字约 120ms，标点停顿）
- 句末有一个呼吸光点，暗示"还有下文"
- 命中句周围有极淡的径向辉光

### 阶段 5：渐进展开解读

- 用户点击命中句区域（或滚动），进入完整解读
- 解读不是一个大文本块，而是分段展开：
  - 第一部分：概述（2-3句），淡入
  - 留白 80px
  - 第二部分：详细解读，逐段 typewriter
  - 留白 60px
  - 第三部分：建议/指引
- 每一段有独立的微标题（金线 + 小字标签）
- 阅读区域最大宽度 620px，居中
- 行高至少 1.8，段落间距至少 24px
- 选中牌在背景中保持可见但极度淡化（opacity 0.15, blur），作为"锚点"

### 阶段 6：重新开始

- 不是明显的按钮，而是在页面底部极淡地出现一行小字：「重新抽牌」
- hover 时微亮，保持低调

## 二、IChing 页面重构

### 核心隐喻：「仪式空间」

当前问题是：6 条爻线在 288px 宽的 div 里，用 `· · ·` 表示未摇爻，旁边跟一个 `btn-primary` 按钮。观感像表单填写进度条。

### 阶段 1：摇卦过程

**改变方向：**

- 爻线符号不再是文字 `━━━━━`，而是视觉元素：**每条爻至少 3 倍于当前尺寸**，占据屏幕中央约 400px 宽
- 未摇的爻不再显示 `· · ·`，而是以极淡的虚线或空白槽位暗示存在
- 每次摇卦后，爻线**从屏幕外"落下"并定位**，带有物理感（不是从 opacity 0 淡入）
- 六条爻从下往上构建（初爻先出现，上爻最后）——但视觉上显示为从上到下（上爻在顶）
- 动爻标识：当前是 `○` 小圆点，改为**脉动的火焰状光点**，直径约 12px，带呼吸动画，标志该爻正在变化
- 摇卦按钮：不应是 `btn-primary`，而应是一个**仪式按钮**——圆形、居中、琥珀光晕、点击时发出涟漪

### 阶段 2：卦象完成——仪式结果

**改变方向：**

- 六爻全部落定后，整列爻线执行一次"锁定"动画——金色脉冲从下到上扫过
- 卦名以大字浮现于爻线上方——text-4xl、serif、tracking-widest
- 卦名上方有装饰性的卦符（☰☰ 等八卦符号），作为视觉标识
- 卦象信息不再以多个 glass-card 堆叠，而是以下方展开的**卷轴式面板**呈现
- 本卦和之卦的关系通过视觉连接展示：本卦在上、之卦在下，中间有向下的箭头或光线连接，动爻位置用光点标出

### 阶段 3：解读模式

**当前问题：** 通俗/专业是两个 tab 按钮 + 纯文本区域。

**改变方向：**

- 模式切换改为更柔和的过渡：一个居中的 pill 切换器，而非卡片内 tab
- 通俗解读：文字以较大的行距、较暖的色调呈现，像是娓娓道来
- 专业解读：文字保持紧凑、古雅，引用的彖辞和象辞以缩进 + 竖线装饰呈现
- 每段解读前有微标签（如「卦辞今译」「彖曰」），使用不同的排版节奏

### 阶段 4：AI 解读

- 与 Tarot 相同的「命中句 → 渐进展开」策略
- 命中句位于卦象下方，留有充足空白
- 卦象在背景中保持可见但弱化

## 三、AI 解读区域 —— 全局重构

### 当前问题

AIResponseCard 是一个 glass-card，里面放 typewriter 文本。观感：Markdown 渲染框。

### 新设计：「耳语」

**命中句（Destiny Sentence）**

- 独立存在，不属于任何卡片
- 居中，serif，text-2xl～3xl，color: amber-200
- 在视口中垂直方向也趋向居中（至少上下各 15vh 空白）
- 逐字浮现，每字约 100-150ms
- 句子以句号结尾后，光标停留 1.5 秒再消失
- 周围有径向光晕，直径约 400px，从文字向外渐变至透明
- 命中句下方 60px 处有一个 subtle 的下箭头或「展开」提示

**渐进展开（Progressive Reveal）**

- 用户点击后，命中句上移至页面顶部约 15% 处（缩小至 text-lg），作为标题锚点
- 正文区域从下方淡入
- 正文分节：
  - 每节有金线分隔（80px 宽，1px 高，水平居中）
  - 节标题：text-sm，amber-200/60，tracking-wider
  - 节正文：text-sm，stone-300，leading-relaxed（约 1.8）
- 每节之间留白 80-100px
- 正文最大宽度 600px，居中
- 整个阅读区域不放在任何 glass-card 内——直接浮在虚空背景上

**节奏控制**

用户视线路径：

1. 命中句（停顿 3-5 秒自然阅读）
2. 视线下移 → 看到分节标题
3. 读一节（约 10-15 秒）
4. 自然停顿（留白制造）
5. 视线继续 → 下一节

不应出现大段文字同时涌入视野的情况。

## 四、全局空间关系

### 深度层级（由后至前）

| 层 | 内容 | 视觉处理 |
|---|---|---|
| L0 | 虚空背景 | 纯暗 #080a0f + 噪点纹理 |
| L1 | 氛围层 | 浮动粒子、径向光晕、微尘 |
| L2 | 非活跃元素 | 未选中牌、弱化卦象：opacity 0.06-0.12, blur 6-8px |
| L3 | 半活跃元素 | hover 中的牌、未完成爻线：opacity 0.5-0.7 |
| L4 | 主要内容 | 选中牌 / 卦象：opacity 1, sharp, glow |
| L5 | 前景 | 命中句、AI 文本：opacity 1, 浮于最前 |

### 留白规则

- 主角元素四周最小留白：120px（移动端 48px）
- 段落间最小间距：24px
- 节间最小间距：80px
- 文本容器最大宽度：620px
- 行宽控制：中文每行 35-50 字

### 模糊层级

- L2 层：`filter: blur(6-8px)` + `opacity: 0.06-0.12`
- 选中牌出现时，网格区动态模糊：从 `blur(0)` → `blur(8px)`，过渡 0.8s
- 命中句出现时，背景牌进一步模糊至 `blur(12px)`

### 光影

- 不使用 CSS box-shadow 硬阴影
- 使用 `radial-gradient` 模拟聚光灯
- 光色温：约 2700K（琥珀金 #fde68a）
- 光强度：主角 0.12-0.18，配角 0.04-0.06
- 过渡区域：光渐变必须 soft（至少 200px 渐变半径）

## 五、视觉节奏

### 用户视线时间线

```
进入页面
  │
  ├─ 0.0s  看到牌阵/卦区（全景扫视，1-2s）
  ├─ 2.0s  hover 某张牌（局部聚焦，0.5s）
  ├─ 3.0s  点击选中
  │
  ├─ 3.0-4.0s  动画高潮：牌脱离/卦锁定的视觉事件
  │             （用户注意力被强行拉向中心）
  │
  ├─ 4.5s  揭示面板出现，用户阅读牌面信息（5-10s）
  ├─ 14.0s 用户点击「请求解读」
  │
  ├─ 14.0-18.0s Loading 动画（呼吸光点，用户进入等待-期待状态）
  │
  ├─ 18.0s 命中句出现（用户停顿、默读，3-5s）
  │
  ├─ 23.0s 用户点击展开
  ├─ 23.0-60.0s 逐节阅读（每节 10-15s）
  │
  └─ 60.0s+ 结束，漂浮的「重新开始」提示
```

关键：每个"停顿"都是设计出来的——通过空间留白和动画节奏强制用户停下。

## 六、实施计划

### 改动范围

**不新增：**

- Token / utility / 设计系统抽象
- 通用组件
- tailwind.config.js 修改
- 品牌色系改动
- 新依赖
- Landing 页面重构（首页 7 个 Section 已有独立结构）

**改动文件：**

| 文件 | 改动内容 |
|---|---|
| `src/components/Tarot/TarotPage.tsx` | 布局彻底重写：聚光灯舞台 |
| `src/components/Tarot/TarotCard.tsx` | 增加"脱离网格"和"聚光灯"状态 |
| `src/components/Tarot/CardReveal.tsx` | 改为侧翼展开式 |
| `src/components/IChing/IChingPage.tsx` | 布局彻底重写：仪式空间 |
| `src/components/IChing/IChingBoard.tsx` | 爻线视觉放大 |
| `src/components/IChing/ThrowButton.tsx` | 改为仪式按钮 |
| `src/components/common/AIResponseCard.tsx` | 改为命中句 + 渐进展开 |
| `src/index.css` | 新增聚光灯、深度层级、模糊过渡等关键 CSS |

### 建议实施顺序

1. **Tarot 页面**（优先）——"选中牌脱离网格"是整个项目视觉升级的核心锚点
2. **AI 解读区域**——命中句 + 渐进展开是全局共享组件，影响两个页面
3. **IChing 页面**——仪式空间改造

## 七、验收标准

完成后，用户应感受到：

- 进入 Tarot 页面时：暗室感，22 张牌隐现于黑暗中
- 点击牌时：视觉高潮——牌脱离、放大、聚光灯亮起
- 阅读 AI 解读时：不像是读文档，而像是听一段耳语
- 进入 IChing 页面时：仪式感，爻线有重量
- 卦象完成时：结果浮现如同一道谕示
- 整体浏览中：有停顿、有焦点、有呼吸
