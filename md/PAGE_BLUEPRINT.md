## 2. 每个页面的核心目标

### 2.1 Landing Page

| 区块 | 核心目标 |
|------|---------|
| Hero | 3 秒内让用户感知"这是一个有温度的神秘空间"，不是工具网站 |
| Mode Gateway | 提供两个明确的仪式入口，降低选择焦虑（只有两个选项） |
| Emotional Resonance | 用一句文案触达用户当下的情绪状态，制造"它懂我"的瞬间 |
| Trust Banner | 消除隐私顾虑——"你的问题不会被存储" |
| Footer | 极简收尾，不分散注意力 |

### 2.2 Tarot Flow

| 阶段 | 核心目标 |
|------|---------|
| Intention | 引导用户将模糊的焦虑凝练成一个问题 |
| Spread | 用牌阵渐入动画制造"命运正在展开"的仪式感 |
| Draw | 让用户在 22 张牌中凭直觉选择——不是理性决策，是直觉牵引 |
| Reveal | 翻牌瞬间制造"命中感"——这一刻不可撤销，不可重来 |
| Interpretation | 让 AI 以温和智者的口吻，将牌面含义与用户的问题编织在一起 |
| Reflection | 给用户一个安静的出口——不催促下一步，允许停留 |

### 2.3 IChing Flow

| 阶段 | 核心目标 |
|------|---------|
| Intention | 同 Tarot——凝练问题 |
| Cast (×6) | 通过 6 次重复的摇卦动作，建立仪式节奏和"不可撤销"的庄重感 |
| Formation | 6 爻齐备后，卦象完整呈现——从单爻到整体的"聚合"时刻 |
| Interpretation | 同 Tarot——AI 以智者的口吻解读，支持通俗/专业双版本 |
| Reflection | 同 Tarot——安静出口 |

### 2.4 Journal（后续迭代）

| 区块 | 核心目标 |
|------|---------|
| Timeline | 让用户看到自己与玄机的"关系史"——每一次问卦都是情绪路标 |
| Entry Detail | 回溯某次占卜的完整上下文 |
| Mood Graph | 让用户看见自己的情绪变化曲线——"原来那段时间我那么焦虑" |

### 2.5 About

| 区块 | 核心目标 |
|------|---------|
| Story | 品牌故事——为什么做玄机 |
| How It Works | 消除神秘化——解释 AI + 占卜的底层逻辑，建立理性信任 |
| Privacy | 用最直白的语言承诺数据安全 |

## 3. 每个页面的用户情绪变化

### 3.1 Landing Page

```
进入 → 好奇（这是什么？）
     → 安静（深色 + 极简，让人慢下来）
     → 沉浸（星云背景 + 微光，被空间包裹）
     → 共鸣（"在不确定中，寻一个安放之处"）
     → 决定（选择一个入口进入）
```

### 3.2 Tarot Flow

```
Intention:
  随意 → 认真（开始思考自己的问题）
       → 期待（输入完成，准备进入仪式）

Spread:
  等待 → 惊喜（牌阵逐张渐入，22 张牌从无到有）
       → 沉浸（牌阵完整呈现，像面对命运的星图）

Draw:
  浏览 → 犹豫（哪张牌在"召唤"我？）
      → 直觉牵引（手指不自觉移向某张牌）
      → 确定（点击——一个不可逆的决定）

Reveal:
  屏息（翻牌动画开始）
     → 冲击（牌面揭示——正位或逆位？）
       → 阅读（快速扫视牌名和关键词）
         → 消化（"这张牌在说我吗？"）

Interpretation:
  专注（AI 文字逐字浮现）
     → 点头（"嗯，有道理"）
       → 被理解（"它真的懂我在想什么"）
         → 释然（得到一个可以安放的答案）

Reflection:
  安静（不需要做任何事）
     → 沉淀（让解读在心里落定）
       → 选择（再来一次？关闭页面？）
```

### 3.3 IChing Flow

```
Intention:
  同 Tarot

Cast (×6):
  第 1-2 次：新鲜感（"铜钱动画好看"）
  第 3-4 次：进入节奏（开始感受仪式的重量）
  第 5-6 次：庄重感（"快结束了，这次问卦是认真的"）
  每次之间：微小的期待（"这一爻会是什么？"）

Formation:
  成就感（6 次完成）
     → 聚合感（分散的爻线组成完整卦象）
       → 敬畏（卦名出现——"这是我的卦"）

Interpretation:
  同 Tarot

Reflection:
  同 Tarot
```

### 3.4 Journal（后续迭代）

```
进入 → 回忆（"上次问卦是什么时候？"）
     → 惊讶（"原来已经问过这么多次了"）
       → 自我觉察（"那段时间我确实很焦虑"）
         → 被陪伴感（"玄机一直在"）
```

## 4. 每个页面的视觉重心

### 4.1 Landing Page

```
┌──────────────────────────────────────────┐
│                                          │
│          [星云背景 · 极淡光斑]             │
│                                          │
│              玄  机                       │  ← 视觉重心 1
│          AI 占卜 · 六爻 · 塔罗             │
│      "在不确定中，寻一个安放之处"          │
│                                          │
│         [开始占卜]  ← 视觉重心 2           │
│                                          │
│   ┌──────────┐    ┌──────────┐           │
│   │  六  爻  │    │  塔  罗  │           │  ← 视觉重心 3
│   └──────────┘    └──────────┘           │
│                                          │
└──────────────────────────────────────────┘
```

**规则**：
- Hero 区垂直居中，大面积留白包围品牌名
- "玄机"二字是最高视觉层级——字号最大、金色、serif、tracking-widest
- CTA 按钮次之——金色发光
- 两种方式卡片再次之——但不抢 Hero 的注意力

### 4.2 Tarot Flow — 各阶段视觉重心

```
Stage 0 (Intention):
  视觉重心 = 输入框。页面极简：标题 + 输入框 + 按钮，其余全是虚空。

Stage 1 (Spread):
  视觉重心 = 整副牌阵。22 张卡背从中心向外 stagger 展开，占满视野。

Stage 2 (Draw):
  视觉重心 = 当前 hover 的牌（微升 + 金色发光边框）。
  其他 21 张牌 = 降级为背景。

Stage 3 (Reveal):
  视觉重心 = 唯一翻开的牌。其余牌 fade 到 opacity 0.2。
  整个页面只存在"这一张牌"。

Stage 4 (Interpretation):
  视觉重心 = AI 文字流。牌退到左上角小尺寸展示。
  注意力从视觉转向文字。

Stage 5 (Reflection):
  视觉重心 = 一句收束文案 + 一个"重新开始"按钮。
  其余全部留白。
```

### 4.3 IChing Flow — 各阶段视觉重心

```
Stage 0 (Intention):
  同 Tarot。

Stage 1-6 (Cast):
  视觉重心 = 爻线展示区。6 条爻线从下往上堆叠，当前爻高亮。
  铜钱动画在爻线上方短暂出现后消失。

Stage 7 (Formation):
  视觉重心 = 卦名。大字、金色、serif、居中。
  卦名是唯一焦点——这一刻用户只应该看到卦名。

Stage 8 (Interpretation):
  同 Tarot。

Stage 9 (Reflection):
  同 Tarot。
```

### 4.4 通用规则

- 每个页面/阶段**只有一个视觉重心**。如果有两个，就是设计失败
- 视觉重心 = 最大字号 + 金色/发光 + 周围大量留白
- 所有非重心元素主动降级：降低 opacity、缩小字号、使用 stone-400/500

## 5. 每个页面的信息层级

### 5.1 信息层级分类

```
L0 — 强调（Emphasize）
  用户必须看到，且会首先看到。
  手法：金色、大字号、serif、发光、居中、周围留白。

L1 — 辅助（Support）
  用户需要时能找到，但不抢注意力。
  手法：stone-300、text-sm、sans、无发光、靠边或底部。

L2 — 弱化（Diminish）
  存在但不显眼。
  手法：stone-500、text-xs、无边框、低透明度。

L3 — 延迟出现（Deferred）
  某个动作完成后才出现，不出现在初始视图。
  手法：motion.div + AnimatePresence + opacity 动画。

L4 — 动态展开（Progressive）
  信息随时间逐步揭示，如 AI 逐字打印。
  手法：typewriter effect、stagger children。
```

### 5.2 Landing Page 信息层级

| 层级 | 内容 | 处理 |
|------|------|------|
| L0 | "玄机" 品牌名 | 居中、金色、serif、5xl |
| L0 | CTA 按钮 | 居中、发光、animate |
| L1 | Slogan | stone-300、居中、比品牌名小两级 |
| L1 | 两种方式卡片 | glass-card、并排 |
| L2 | Trust Banner 文字 | stone-500、底部、小字 |
| L3 | （无） | — |

### 5.3 Tarot Flow 信息层级

```
Stage 0 — Intention:
  L0: 输入框（focus 态发光边框）
  L1: 页面标题"塔罗抽牌"
  L2: placeholder 引导文案
  L3: 提交后 → Stage 1

Stage 1 — Spread:
  L0: 整副牌阵
  L1: 页面标题
  L2: 已输入的问题（顶部小字显示）
  L3: （无）

Stage 2 — Draw:
  L0: hover 的牌（金色发光）
  L1: 其余牌（正常态）
  L2: 提示文案"凭直觉选择一张牌"
  L3: 点击后 → Stage 3

Stage 3 — Reveal:
  L0: 翻开的牌面（全尺寸、居中）
  L1: 牌名 + 正逆位标签
  L2: 关键词标签
  L3: 其余 21 张牌 → opacity 0.2
  L3: 翻牌完成后 → "请求解读"按钮出现

Stage 4 — Interpretation:
  L0: AI 解读文字流（逐字浮现）
  L1: 已翻开的牌（缩小至左上角）
  L2: 问题回顾（顶部小字）
  L3: 解读模式切换 tab

Stage 5 — Reflection:
  L0: （无强制焦点——让用户自己决定看什么）
  L1: "重新开始"按钮
  L2: 一句收束文案
```

### 5.4 IChing Flow 信息层级

```
Stage 0 — Intention:
  同 Tarot

Stage 1-6 — Cast:
  L0: 爻线展示区（当前爻高亮）
  L1: 摇卦按钮（显示次数进度）
  L2: 已输入的问题
  L3: 铜钱动画 → 短暂出现后消失
  L3: 6 次完成后 → "解卦"按钮出现

Stage 7 — Formation:
  L0: 卦名（大字、金色、居中）
  L1: 上下卦信息 + 卦序编号
  L2: 卦辞引用
  L3: 变卦信息（如有动爻）
  L3: "请求解读"按钮

Stage 8 — Interpretation:
  同 Tarot

Stage 9 — Reflection:
  同 Tarot
```

## 6. 页面之间的节奏变化

### 6.1 节奏类型定义

```
┌────────────┬──────────────────────────────────────────┐
│ 节奏类型    │ 特征                                      │
├────────────┼──────────────────────────────────────────┤
│ 慢 · 安静   │ 大面积留白、无动画、静态布局               │
│            │ 用户行为：阅读、沉淀、思考                  │
│            │ 代表：Reflection、Interpretation、About    │
├────────────┼──────────────────────────────────────────┤
│ 中 · 聚焦   │ 有单一视觉重心、可能有一个动画              │
│            │ 用户行为：输入、选择、决策                   │
│            │ 代表：Intention、Draw                      │
├────────────┼──────────────────────────────────────────┤
│ 快 · 仪式   │ 有 staged 动画序列、不可逆的单向推进        │
│            │ 用户行为：观看、等待、感受                   │
│            │ 代表：Spread、Reveal、Cast、Formation       │
└────────────┴──────────────────────────────────────────┘
```

### 6.2 全流程节奏地图

```
Landing ──────── 慢 · 安静
  │
  ├─→ Tarot Intention ── 中 · 聚焦
  │     │
  │     ├─→ Spread ──── 快 · 仪式（牌阵 stagger 渐入）
  │     │     │
  │     │     ├─→ Draw ── 中 · 聚焦（用户犹豫、选择）
  │     │     │     │
  │     │     │     └─→ Reveal ── 快 · 仪式（翻牌高潮）
  │     │     │           │
  │     │     │           └─→ Interpretation ── 慢 · 安静（逐字阅读）
  │     │     │                 │
  │     │     │                 └─→ Reflection ── 慢 · 安静（沉淀）
  │     │     │
  │     │     └─（用户随时可选牌，节奏由用户控制）
  │     │
  │     └─（Spread → Draw 之间无硬边界，自然过渡）
  │
  ├─→ IChing Intention ── 中 · 聚焦
  │     │
  │     ├─→ Cast ×6 ── 快 · 仪式（重复但有递进）
  │     │     │        每次摇卦 = 一个小高潮
  │     │     │        6 次之间 = 短暂的安静间隙
  │     │     │
  │     │     └─→ Formation ── 快 · 仪式（聚合高潮）
  │     │           │
  │     │           └─→ Interpretation ── 慢 · 安静
  │     │                 │
  │     │                 └─→ Reflection ── 慢 · 安静
  │     │
  │     └─（Cast 节奏由按钮控制，用户主动触发每次摇卦）
  │
  └─→ Journal ──── 慢 · 安静（后续迭代）
```

### 6.3 节奏设计原则

1. **快慢交替**：仪式高潮后必须接安静阶段。用户不能在连续的高刺激中停留
2. **慢进慢出**：进入仪式前的 Intention 和离开仪式后的 Reflection 都是"慢"的
3. **用户控制节奏**：Draw 和 Cast 的推进由用户主动触发，不由系统自动推进
4. **AI 解读不可快进**：逐字打印期间用户不能跳过

## 7. 哪些地方必须加入动效

### 7.1 动效必要性分级

```
必须 — 没有动效，这个阶段的核心体验就不成立
建议 — 动效显著提升体验，但没有也能工作
可选 — 锦上添花
```

### 7.2 必须加入动效的节点

| 页面/阶段 | 动效 | 原因 |
|-----------|------|------|
| Landing Hero | "玄机" 二字 fade-in + 微升 (400ms) | 品牌第一印象必须有仪式感 |
| Tarot Spread | 22 张牌 stagger 渐入（每张 30ms 延迟） | "命运之轮展开"的核心体验 |
| Tarot Draw | hover 牌微升 + 金色边框发光 | 直觉牵引的物理反馈 |
| Tarot Reveal | 翻牌动画（rotateY 0→180°, 600ms） | 整个塔罗流程的高潮 |
| Tarot Reveal | 其余牌 fade 到 0.2 (300ms) | 制造"只有这一张牌存在"的聚焦 |
| IChing Cast | 铜钱抛出 → 旋转 → 落定 (700ms) | 摇卦的核心仪式 |
| IChing Cast | 爻线 scaleY(0→1) 出现 (400ms) | 每爻落定的视觉反馈 |
| IChing Formation | 6 条爻线 → 卦名出现的过渡 (500ms) | 从"分散的爻"到"完整的卦"的聚合感 |
| Interpretation | AI 文字逐字打印（30ms/字） | 模拟"智者沉吟" |
| Interpretation | 模式切换平滑过渡 | 通俗/专业切换不应有跳动 |
| 所有页面 | 页面过渡 fade (250ms) | 避免生硬感 |
| 所有按钮 | hover glow 扩散 (200ms) | "光"的核心视觉语言 |
| 所有按钮 | active scale(0.97) (100ms) | 按压反馈 |
| Loading | 呼吸式光点脉冲 (2000ms/cycle) | 替代 spinner |

### 7.3 建议加入动效的节点

| 页面/阶段 | 动效 |
|-----------|------|
| Landing | 两种方式卡片 hover 微升 |
| Tarot Detail | 详情面板从牌中"生长" (300ms) |
| IChing Board | 空爻线占位虚线 → 实线过渡 |
| Reflection | "重新开始"按钮延迟 1s 后 fade-in |
| ModeSelector | 切换模式时内容区 fade |
| QuestionInput | focus 态边框发光扩散 |

### 7.4 不需要动效的节点

| 位置 | 原因 |
|------|------|
| 正文段落 | 文字本身已经足够 |
| Footer | 最底层信息，动效是干扰 |
| Trust Banner | 信任信息应该"安静地存在" |
| 英文牌名 | 辅助信息不需要动态强调 |
| 禁用态按钮 | 光已熄灭，不再动 |

## 8. 哪些地方必须保持极简

### 8.1 极简的定义

在本产品中，"极简" = **信息密度极低 + 大面积虚空 + 只有一个可交互元素**。

### 8.2 必须极简的页面/区域

| 页面/区域 | 极简到什么程度 | 原因 |
|-----------|---------------|------|
| Landing Hero | 只有品牌名 + Slogan + 一个按钮。其余全部虚空。 | 第一印象决定用户是否留下 |
| Intention 阶段 | 只有标题 + 输入框 + 一个按钮。 | 用户正处于"准备问卦"的心流中 |
| Reveal 阶段 | 只有一张牌 + 牌名。其余 21 张 fade 到近乎消失。 | "命中感"需要绝对的视觉聚焦 |
| Formation 阶段 | 只有卦名。爻线退到次要区域。 | 用户唯一想知道的是"什么卦" |
| Reflection 阶段 | 只有一句收束文案 + 一个按钮。 | 这是用户"消化"的时间 |
| 导航栏 | 只保留两个模式切换按钮。 | 导航栏只是"你在哪个仪式中"的标识 |
| Footer（所有页面） | 一行版权信息。 | 底部是空间的自然边界 |

### 8.3 极简的敌人

| 禁止出现的元素 | 理由 |
|---------------|------|
| 面包屑导航 | 仪式不需要"你在哪里"的定位 |
| 侧边栏 | 破坏"虚空包围"的空间感 |
| 多处 CTA 按钮 | 每个页面只有一个主行动 |
| 信息密度高的表格/列表 | 后台管理感、工具感 |
| 弹窗/对话框 | 打断仪式——除非是错误提示 |
| 社交分享按钮 | 占卜是私密的、个人的 |
| "你可能还喜欢"推荐 | 商业化气息破坏神秘感 |
| 评分/反馈入口 | 仪式结束后不要问用户"满意吗" |

## 10. 空间感设计原则

### 10.1 核心命题

> 如何让页面不像"网页"，而像一个"数字仪式空间"？

答案：打破浏览器的"页面"隐喻，构建"空间"隐喻。

### 10.2 十大空间感原则

**原则 1：无边界的虚空**

- 页面底色 `#080a0f` 铺满整个视口，不留白边
- 不使用白色/浅色背景的任何区域
- 内容不从"页面顶部"开始——从"虚空深处"浮现
- 卡片没有"落在地面上"的感觉——它们"悬浮在虚空中"

**原则 2：光是空间的标尺**

- 光晕的强度 = 物体到用户的距离
- 越近 → 光晕越强（如 Modal）
- 越远 → 光晕越弱（如背景卡片）
- 没有光晕 = 沉入虚空深处

**原则 3：空间由"空"定义，不由"有"定义**

- 一个页面的"空间感"来自留白的面积，而非内容的密度
- 如果一个页面 80% 是虚空、20% 是内容——这是对的
- 如果虚空少于 50%——重新设计

**原则 4：过渡是"空间穿梭"，不是"页面切换"**

- 路由变化 = 在同一个空间中重新聚焦
- 用 fade 过渡，不用 slide
- Slide = 物理空间移动 → "页面"隐喻
- Fade = 光的变化 → "空间"隐喻

**原则 5：星云背景是空间的"墙纸"**

- 两处极淡的径向渐变（左上 + 右下）模拟深空光斑
- 永远静止，不随滚动移动
- 不可交互——它是空间本身，不是页面元素

**原则 6：玻璃即"窗"——透明 = 诚实**

- 所有卡片使用半透明底 + backdrop-blur
- 用户透过卡片能看到"背后的虚空"
- 不透明卡片 = 墙 → 阻隔感
- 透明卡片 = 窗 → 通透感

**原则 7：导航栏是空间的"门框"，不是"工具栏"**

- 只标记当前位置（六爻/塔罗）
- 不承载功能入口
- 毛玻璃底——门框本身也是透明的

**原则 8：一次只在一个"房间"里**

- 没有 split-view、没有侧边栏、没有多列布局（除 Landing 的模式选择）
- 用户在任何时刻只能做一件事
- 这不是功能限制——这是仪式要求

**原则 9：滚动是"空间纵深移动"，不是"翻页"**

- 信息通过滚动渐进揭示（如 Landing 的多段结构）
- 不是"翻到下一页"——是"向空间深处行进"

**原则 10：移动端是"掌中空间"，不是"缩小版桌面"**

- 移动端不是桌面端的等比例缩放
- 通过减少同时可见的元素数量来维持虚空比例
- 塔罗牌阵在移动端每行 5-6 张——保留牌与牌之间的呼吸间隙

### 10.3 避免的"页面感"陷阱

```
陷阱                              │ 为什么破坏空间感
──────────────────────────────────┼────────────────────────────
白色/浅色背景                     │ 像文档/工具，不像空间
明显的页面边框/容器边框           │ 提醒用户"这是浏览器窗口"
scrollbar 显眼                    │ 提示"你在滚动一个页面"
header/footer 有背景色            │ 像网站模板
卡片有 Y 轴投影                   │ "落在地面上"—物理世界隐喻
面包屑导航                        │ "你在网站结构的某个位置"
多处 link / CTA                  │ 像导航页面，不像仪式空间
footer 有大量链接                 │ 典型的企业网站 footer
```
